# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **The transcript now holds what the user actually typed, not the prompt scaffolding.** `ask_stuff` used to checkpoint the fully-framed prompt, so the message stored for "what is dirtying my git status?" was `Context:\n User is texting from Discord (User ID: nick)\n Question:\n …`. Three consequences, all now fixed: the web chat rendered that verbatim as the user's own message on every reload (telling a browser user they were "texting from Discord"); every replayed turn in the history window carried the boilerplate again, spending context on instructions the model had already acted on; and stale per-turn instructions leaked forward — a `DISCORD_VOICE` turn's "answer in 30 words or less" stayed in the transcript and kept pressuring later text replies to be terse. The framing now travels in `additional_kwargs["ctx"]` and `format_turn()` re-applies it to the current turn only, on its way to the model. Verified end to end against a live Ollama: history reads as plain user text, and a two-turn recall ("my favourite colour is oxblood" → "what is my favourite colour?") still answers correctly, so the model lost nothing.
  - Side benefit: the per-message memory query embeds the user's actual words instead of the boilerplate, which should sharpen retrieval.
  - Noted while here, deliberately **not** changed: `format_prompt`'s `additional_info` parameter has never been interpolated — it appears in the signature and nowhere in the body, so the `" User has attached images: […]"` string passed for image turns has always been discarded. Wiring it up would change what the model sees on every image turn; the paths already reach the agent via config metadata.
- **The no-JS `POST /chat/send` fallback is gone (DECISIONS.md #3, finally applied).** It was a second, diverging copy of the `ask_stuff` + `_render_markdown` wiring that every chat change had to be made in twice, and it had already drifted — it rendered raw exception text back to the user and omitted `is_admin`, so the page lost its controls after any error. Nothing proved a real no-JS browser worked through it. `/chat/stream` is the only send path; the composer form carries no `action` and every submit handler cancels the native POST. The two pending-image tests that exercised it moved to `/chat/stream`, which is where that plumbing actually lives now.
- **`DECISIONS.md` #16 finished.** The expensive third (the code-block language label) had shipped while both cheap ones were dropped — the reverse of what the decision asked for.
  - Messages now carry a creation timestamp. LangGraph checkpoints have no time of their own, so `mister_fritz` stamps `additional_kwargs["ts"]` when the message is built; without it the chat could only show times for messages it watched arrive live, and every reload looked like the timestamps had been lost. History written before this renders with no time rather than an invented one. The `<time>` element keeps the ISO instant in `datetime=` and displays the viewer's local short time, so a UTC stamp reads correctly in any zone.
  - `chat_upload_image` returns `width`, `height` and `format` alongside the URL, read off the sniffed bytes rather than anything the client asserted, and sent images render as the framed card with a `1440×900 · PNG` caption.

### Fixed
- **Two heavy imports still ran on the Discord event loop.** Deferring them off module scope kept the extras optional but left the module body executing on the loop — the freeze the offload existed to remove, just relocated. `bot_commands.gen_slash` imported `image_generator` (~10s, on the first `/gen` after every restart) and `on_ready` imported `tts` (~17s, past discord.py's "heartbeat blocked for more than 10 seconds" threshold on every boot with `[voice]`). Both imports now sit inside the callable handed to the worker pool. Cold start for the `main_discord` chain drops from ~14.6s to ~7.3s, and `tests/test_packaging.py::TestHeavyImportsRunOffTheEventLoop` guards the shape — the failure mode is a latency regression with no functional symptom, so nothing else would catch it.
- **Post-implementation audit — four defects.** Found by auditing the shipped code against each plan's Definition of Done, then reproducing each one.
  - **The global CSP had silently disabled every admin confirmation.** `_SecurityHeadersMiddleware` applies `script-src 'nonce-…'` (no `'unsafe-inline'`) to *every* response, not just `/chat` — and a nonce cannot attach to an inline event-handler attribute. The three admin forms still on `onsubmit="return confirm(...)"` — cancel schedule, disable workspace, and **"Permanently delete ALL data for &lt;user&gt;"** — therefore POSTed with no prompt at all. Exactly the defect class `chat.html` was fixed for, on the most destructive button in the app. Confirmations now come from a nonce'd delegated handler in `base.html` keyed off `data-confirm`. Verified in a browser under the real CSP: the prompt fires and cancelling stops the submit.
  - **`execute_command` argument containment was inert on Windows.** The check was guarded by `os.path.isabs()`, but `ntpath.isabs()` returns False for `/etc/passwd`, `\Users\me\.ssh\id_rsa` and the drive-relative `C:x` — so every one of those skipped the workspace check and ran. `posixpath.isabs()` returns True for the first, which is why this only ever failed on one platform. Replaced with `_is_rooted()`, which treats a leading separator or a drive prefix as rooted everywhere. Relative arguments still resolve against the workspace as before.
  - **The memory-injection cap deleted memories instead of shortening them.** The keep-loop breaks on the first entry that crosses `MEMORY_INJECT_MAX_CHARS`, so a lone oversized memory left `kept` empty and `json.dumps({})` == `"{}"` — the prompt carried the literal text `What I know about this user:\n{}` and the most relevant memory was gone. Not a corner case: `summarize_conversation` writes one large value per memory and a long thread's summary routinely exceeds the budget. Now falls back to a character cut, and an empty result no longer emits the header at all.
  - **One chat user could read another's uploads.** Ownership was a filename-prefix test, but `_` is a legal identity character, so `"web-alice_"` also prefixed `web-alice_2`'s files. Uploads now go to a per-user directory (`temp_images/<safe_user>/`) compared with `==`, which has no such ambiguity.

### Added
- **Phase 15 — the web chat restyle ("the butler restyle").** The chat surface is now dark academia: candle-lit purple, serif type, zero border-radius, faceted `clip-path` geometry throughout. It has its own chrome (`chat_base.html`) rather than the admin panel's, because the shell is a fixed flex column whose transcript scrolls in its own container — and because chat users were being shown six admin nav links, five of which led to a password prompt they had no password for.
  - The theme splits three ways — `_theme_base` (reset, focus, motion policy; shared), `_theme_admin`, `_theme_chat` — so the admin panel keeps its plain utility look. Tokens are layered (channel triplets → named alpha steps → semantic) so an accent can be retuned in one place instead of across ~41 hand-typed `rgba()` literals.
  - Streaming UX: a status chip that swaps copy after 1.4s, a blinking caret trailing the text, and an **"Enough"** stop button. Stop is labelled honestly — it aborts the client fetch, but `chat_stream` runs `ask_stuff` on a daemon thread that never checks `is_disconnected()`, so the model keeps generating and the notice says so.
  - `applyToken(delta, accumulated, restart)` isolates the wire format. Token frames are cumulative today; when that flips to deltas, that one function changes and the stream reader, caret and scroll-follow keep working.
  - `window.confirm()` and all three `alert()` calls are gone — replaced by a faceted confirm dialog (labelled, focus-managed, dismissible by veil click, Escape or "Spare it") and an inline notice bar where info auto-dismisses and errors do not.
  - Syntax highlighting via `codehilite` with `guess_lang=False` (on, it colours prose and log dumps as if they were code), gated by `CHAT_CODE_HIGHLIGHT`. Code blocks get a title bar with the fence's language and a copy button whose clipboard fallback chains rather than branches — `navigator.clipboard` is absent over plain http *and* rejects transiently when the document is unfocused.
  - Self-hosted fonts via a new `/static` mount, so a 127.0.0.1 panel never beacons to a third party. **The `woff2` files are not in the repo** — see `admin_static/README.md`; until they are added the page falls back to system serifs and is fully usable.
  - Deliberately deviating from the design in three places, each for a reason recorded in the code: the seal's glow uses `filter: drop-shadow` because `clip-path` clips `box-shadow` (the prototype's own glow is invisible); scan lines render beneath content, because an above-content `mix-blend-mode: overlay` layer tints every glyph and would undo the contrast fixes; and three palette colours were lightened because they failed AA against the composited background, one of them worse than the admin bug this redesign exists to fix.

### Fixed
- **Phase 15 — Discord surface polish.** The bot leaked raw Python exception strings to users, broke character in five places, spammed channels with permanent progress messages, split long replies mid-word and mid-code-fence, and had no app-command error handler at all — so `/draw 500` raised an uncaught `HTTPException` and the user saw nothing but a spinner.
  - `split_into_chunks` is now boundary- and fence-aware: it breaks on paragraph/line/word boundaries where one exists, and closes an open ``` fence before reopening it — with its language tag — on the next chunk. Without that, Discord renders the tail of a split code block as prose and everything after it as code. A separator in the first half of the window is deliberately ignored: honouring a newline at index 10 of a 2000-char budget would waste the rest of the message.
  - New `bot_adapters.fritz_error(operation, exc)` records the exception to `METRICS` and the log, returning butler copy with a short ref to grep for. Six Discord sites now use it — and so does the web chat's SSE `error` frame, which had the identical leak.
  - `cog_app_command_error` plus a `tree.on_error` backstop catch everything a slash command can raise, replying ephemerally and picking `followup` vs `response` based on whether the interaction already deferred.
  - `/help`, `/about`, `/health` and `/schedule list` are now embeds in the project accent colour. **`/health` is ephemeral** — it was the one interaction reply posting metrics into channel history for everyone.
  - `/about` reported `0s` uptime on every invocation: it read `uptime_seconds`, but `observability` emits `uptime_sec`, and the `.get` default swallowed the miss.
  - `/draw` is bounded by `app_commands.Range[int, 1, 40]`, so Discord rejects an out-of-range value before the command body runs.
  - Tool progress now renders **inside** the streaming placeholder instead of as separate permanent `channel.send`s that could land *below* the message they described, and clears when the reply lands. The mid-stream `[:2000]` head-truncation became a tail window, so a long reply keeps showing the newest tokens rather than freezing on a stationary prefix; `final_update` now owns chunking, which `on_message` used to duplicate.
  - `temp_audio/` files are tracked and cleaned up at both exit paths (the directory had grown since the feature shipped), and the audio attachment branch gained the `try/except` the image branch already had — without it a transcription failure escaped `on_message` entirely and the user got no reply.
- **Phase 15 — the executor can finally see the conversation.** The ReAct sub-agent was handed exactly `[system_prompt, latest_user_message]` every turn, and it is compiled *without* a checkpointer — so LangGraph's per-user SQLite history accumulated faithfully and the model never read a word of it. In-thread continuity depended entirely on lossy background Chroma extraction; "what did I just ask you?" was unanswerable from the transcript. The executor now passes a token-budgeted suffix of `state["messages"]` (`trim_messages`, `strategy="last"`, approximate chars/4 counter — there is no tokenizer for `gpt-oss`), governed by `HISTORY_TOKEN_BUDGET` (default 4096; `0` disables and reproduces the old single-message input byte-for-byte, which is the rollback lever and is covered by a test).
  - This only became worth doing once replies were stored as `AIMessage`: before that fix the window would have been an unbroken run of `HumanMessage`s with Fritz's own answers indistinguishable from the user's.
  - `trim_messages` returns `[]` when the newest message alone busts the budget (verified, not assumed). Both executor branches fall back to sending that message alone rather than handing the model a system-prompt-only input.
  - `count_tokens_approximately` is imported from `langchain_core.messages.utils`, **not** `langchain_core.messages` — it is not re-exported there and the obvious import raises `ImportError` at startup.
  - The auto-injected Chroma memory blob is now capped by `MEMORY_INJECT_MAX_CHARS` (default 4000). `search_memories_internal` pulls up to 30 stored conversation summaries with no size limit; uncapped it could evict the window — and the Fritz persona itself — from `num_ctx=32768`. Least-relevant entries are dropped first, since Chroma returns similarity-ordered results.
  - New `history_window_trimmed`, `history_window_overflow` and `memory_inject_truncated` counters, so how often the budget actually binds is visible in `/health`.
- **Phase 15 — "New conversation" asks before destroying a thread.** The button carried `onsubmit="return confirm('…only this thread\\'s context is reset.');"`. HTML attribute parsing does not process backslashes, so the JavaScript the browser actually compiled contained an escaped backslash followed by a bare `s` — a `SyntaxError`. A handler that fails to compile is `null`, so `POST /chat/forget` fired with no prompt at all, and `privacy.forget_conversation` `DELETE`s from `checkpoints` and `writes` unrecoverably. The confirmation is now registered with `addEventListener` — deliberately *above* the `if (!form || !list) return;` guard, since below it a missing composer would silently disarm the prompt again. A test asserts that ordering.
- **Phase 15 — the admin panel and chat work on a phone.** `base.html` had no viewport meta and no `@media` rule anywhere in the eight templates, so mobile browsers rendered at desktop width and scaled down. Adds the viewport meta (covering every template at once), a 700px breakpoint that stacks the header, narrows the bubble insets and scrolls wide tables inside their own box rather than the page, and raises both composers to a 16px floor — iOS Safari force-zooms a focused input below that and never zooms back out. Focus is no longer pulled back to the textarea on touch devices after a send, where it re-opened the soft keyboard over the reply.
- **Phase 15 — the transcript is announced to screen readers.** `#chat-messages` was a bare `<div>`: no role, no live region, no busy state. It is now `role="log"` with `aria-live="polite"`, paired with a visually-hidden `#chat-status` region and an `aria-busy` flag so assistive tech is told a reply is composing instead of trying to announce every partial token. A `prefers-reduced-motion` block stops the decorative streaming caret for users who ask for it.
- **Phase 15 — two `chat_send` render bugs.** The no-JS fallback rendered `chat.html` without an `is_admin` key, so the admin upload panel silently vanished after a sync send, and its error-path message dicts omitted `html`, so an error reply skipped the markdown branch.

### Changed
- **Phase 15 — the dependency freeze is gone.** `requirements.txt` was a raw 292-line `pip freeze` that carried a 2016-era neuroimaging stack into every install and every CI run. Dependencies are now declared intentionally in a `[project]` table in `pyproject.toml` with `voice` / `image` / `ocr` / `telegram` / `dev` / `all` extras; `requirements.txt` is the pinned lock of that set and remains a hand-reviewed freeze (`plans/DECISIONS.md` #9 — no pip-tools, no uv). 37 pins removed, one added.
  - **`fitz==0.0.1.dev2` is gone, and this was worse than a dead pin.** That distribution is unrelated neuroimaging software (`Fitz: Workflow Management for neuroimaging data`, Python 2.7) which installs into the *same* `fitz/` directory PyMuPDF uses. Both file manifests claim `fitz/__init__.py`, so whichever wheel lands last wins. On the machine this was developed on the neuroimaging one had already won outright — `import fitz` raised `ModuleNotFoundError: No module named 'frontend'` (a Python 2 implicit relative import) and PyMuPDF was not installed at all, so scanned-PDF OCR had been silently off. The more dangerous ordering is the other one: `import fitz` *succeeds*, `document_engine`'s `except ImportError` guard never fires, and `fitz.open()` raises `AttributeError` inside PDF ingestion instead. **Uninstalling is itself a trap** — `fitz`'s manifest lists `fitz/__init__.py`, so `pip uninstall fitz` deletes PyMuPDF's shim; PyMuPDF must be force-reinstalled after. `tests/test_packaging.py::test_no_fitz_distribution_is_installed` is the acceptance signal and fails on the pre-change environment.
  - Also removed: the whole `fitz` → `nipype` chain it dragged in (nibabel, nipype, pyxnat, traits, prov, rdflib, simplejson, configobj, configparser, acres, ci-info, etelemetry, looseversion, puremagic, pydot, httplib2), the six-package `google-*` chain rooted solely at `langchain-google-community`, packages with zero import sites anywhere in the repo (pygame, pyttsx3, pdf2image, pytesseract, ffmpeg, ffmpeg-python), and `pathlib==1.0.1` — the Python 2 backport, sitting on `sys.path` since some ancient freeze. **`zstandard` was added**: `faster-whisper` needs it and the old freeze never listed it, so the "lock" did not actually lock.
  - **The core is now torch-free.** `bot_commands` imported `generate_image` and `TTSEngine` at module level, and `main_discord` imports `bot_commands` — so the entire multi-GB GPU stack was a hard requirement just to *start* the bot, for someone who might never run `/gen` or `/voice`. Both are deferred to the point of use, matching what `agent_tools.generate_image` already did. Without the extras those features now report themselves unavailable instead of crashing: `/voice` replies in character that it has no voice on this instance.
  - **Pillow moved into core, and that was a live bug.** It sat in the `image`/`ocr` extras, but `admin_panel._sniff_image_format` decodes an upload to prove it really is an image rather than trusting the declared `Content-Type` — that is the security control on chat image uploads. Without Pillow it returns `None` for everything, so the endpoint 415s on every upload: fails closed, but the feature is simply dead. Found by running the suite in a genuinely core-only venv, where four tests went red.
  - **`nh3` and `Pygments` are pinned with a comment explaining why they must never be dropped.** Neither is obvious from a call graph — nh3 is used in one helper and Pygments is never imported by this codebase at all (markdown's `codehilite` imports it) — so a well-meaning "remove unused packages" pass takes both, and with them the XSS sanitiser. `tests/test_packaging.py` fails if either leaves.
  - CI: `cache: pip` on `actions/setup-python` (previously absent, so every run re-downloaded the whole closure), `pip install -e ".[dev]"` instead of the full freeze, and a new `python scripts/check_imports.py` step. That smoke check earns its place — `pytest` alone cannot catch a core dependency dropped from the set, because `tests/conftest.py` stubs the heavy optional modules, so a module can pass its tests and still fail on a real boot. A separate `full-deps` job installs `.[all]` against the PyTorch CPU index, on schedule and dispatch only.
  - `Dockerfile` no longer installs `tesseract-ocr`. The comment claimed "OCR fallback for scanned PDFs", but the OCR engine is `easyocr` and `pytesseract` is never imported anywhere. Dead apt layer.
  - `browser_tools.py` is deleted rather than wired up (`DECISIONS` #7), so playwright never enters the dependency set — nothing imported the module and `get_browser_tools_description` had no callers. **Its 8000-character page cap was NOT lost**: `agent_tools.scrape_web` never had one, and an uncapped scrape of a single long article can evict the conversation window from `num_ctx`. It is now `SCRAPE_MAX_CHARS`, with a test.
  - Verified rather than assumed: a clean venv with `pip install -e ".[dev]"` installs 189 packages with no torch, no `nvidia-*`, no diffusers, no coqui-tts, no easyocr; all 20 core modules import; and the full suite passes there (707 tests, 82.77% coverage) as well as in the extras-present environment.

### Security
- **Phase 15 — stable namespaced identity.** Every store was keyed off a mutable, platform-ambiguous display string, and *four different transformations* of that string were applied at four layers — `mister_fritz.ask_stuff`, `privacy._sanitise_thread_id`, `admin_panel._load_chat_history` and `workspace_store._safe_user_dir`, each with its own charset. There is now exactly one: `fritz_utils.canonical_user_id(platform, raw_id)` producing `discord-123456789` / `telegram-987654321` / `web-alice`, minted at each of the four adapter boundaries and passed **verbatim** into the Chroma namespace, the LangGraph `thread_id`, the `schedules` / `workspaces` tables and the admin gate. `re` is no longer imported by `privacy.py` at all.
  - **A Discord rename no longer revokes your own admin rights**, nor orphans your memories, workspace and schedules — and no longer hands them to whoever takes the name next. `is_admin(user_id, display_name=None)` gates on the id; the display-name path exists only under `ADMIN_LEGACY_NAME_MATCH`, which ships **false** so there is no impersonation window, not even for one release. `validate_config()` logs a warning naming every non-canonical `ROOT_USER`/`ADMIN_USERS` entry.
  - **`/forget memories` actually deletes now.** `privacy.forget_memories` called `delete_namespace((str(user_id),))` with the *raw* id while `agent_tools.add_memory` wrote with the *stripped* one, because `ask_stuff` stripped the id before putting it in metadata and the executor read it back from there. For any username containing punctuation the two never matched: the command reported success and removed nothing. `export_memories` had the identical mismatch, which is why the admin panel's per-user memory counts read 0 for those users. A test asserts the write and delete namespace tuples are byte-identical, and five tests fail if the old `re.sub` is reintroduced.
  - The separator is a **dash, not a colon** (`plans/DECISIONS.md` #5). A colon is illegal in a Windows filename and silently creates an NTFS alternate data stream on write, and identities reach filenames in `main_discord` attachment saves, `workspace_store` directories and `chat_upload_image`. `split_user_id` partitions on the first dash against a closed platform allowlist, so a legacy name containing a dash (`jean-luc`) is correctly reported as legacy rather than misread, and `web-alice-bob` still resolves to platform `web`, id `alice-bob`.
  - Human-readable names survive in a new `user_aliases` table (`identity_store.py`) rather than by *being* the key — read by the prompt builder, the admin panel's user list, and the scheduler, which has no live user object when a cron job fires hours later. `/forget all` drops the alias too; a "forget me" that still knows what you are called has not forgotten you.
  - **`migrate_identity.py`** rewrites the existing rows in all five stores. Dry-run by default; `--apply` writes its mapping JSON *before* mutating anything and refuses to run if any discovered key is unmapped, rather than leaving the stores half-migrated; `--reverse` restores the original state exactly. Chroma metadata is rewritten in place with `collection.update()`, so **Ollama does not need to be running and nothing is re-embedded** — a test asserts the embedding vector is byte-identical afterwards. It tolerates the missing `workspaces` table, which the live database genuinely does not have.
  - **Breaking, and it needs a manual step.** Run the migration with the bot stopped, then set `ROOT_USER` to the canonical form in `.env` *before* restarting — otherwise you lose admin commands. See the new Identity section in the README.
  - **`CHAT_SHARE_DISCORD_THREAD` and `CHAT_THREAD_PREFIX` are retired.** The `web-` namespace now lives in the identity itself, so the prefix has nothing left to do, and `IDENTITY_LINKS` replaces the sharing flag — it links the whole identity, so memories, schedules and workspace follow the conversation across surfaces instead of being left behind. Followed exactly one hop, so a chain is not transitive and a cycle cannot hang a request.
  - `THREADS_PER_CHANNEL` (default **false**) gives one thread per identity per channel, so a conversation in #general stops bleeding into DMs. Turning it on **branches every existing conversation**: the identity-only thread stays in the database untouched, but new messages start a fresh per-channel thread and the old context is no longer read. `/forget conversation` sweeps `<identity>` and every `<identity>#<channel>`, and the `#` is what makes that safe — `discord-1#%` cannot match `discord-10#general`. `LIKE` wildcards in an identity are escaped, since `_` is legal in one and means "any character" to `LIKE`.
  - Deviation from the plan, deliberate: the card deck now keys on the identity with the display name passed alongside for the prose, rather than keeping `interaction.user.name` as the key. The plan judged it not worth changing because `USER_DECKS` is in-memory, which is true — but a rename mid-session silently handing you a fresh deck is still wrong, and the fix was three lines.
- **Phase 15 — Content-Security-Policy on the panel.** Every response now carries `default-src 'none'` with a per-response nonce on `script-src`, plus `nosniff`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer`. A nonce-only `script-src` kills both an injected `<script>` and an inline `onerror=` handler if anything ever slips past the nh3 sanitiser — defence in depth, not a replacement for it.
  - `style-src` deliberately keeps `'unsafe-inline'` and has **no** nonce: adding one makes `'unsafe-inline'` be ignored outright, and every `style=""` attribute and `<style>` block on the page dies. `font-src 'self'` is likewise mandatory or every `@font-face` is blocked, self-hosted or not.
  - `chat_asset` keeps its own stricter sandboxing CSP — the middleware uses `setdefault`, and a test asserts the looser page policy does not overwrite it.
- **Phase 15 — document upload moved off the chat surface.** `POST /chat/upload/document` gated on `fritz_utils.is_admin(user)` where `user` was the *self-asserted* name from the chat cookie — so anyone holding the chat password could type the owner's username and inject documents into `DOC_FOLDER`, the shared corpus every user's RAG queries are answered from. **Breaking:** that route is gone. The capability now lives at `POST /documents/upload` behind the admin panel's existing HTTP Basic auth, with an upload form on the Documents page; extension check, size cap and path-escape guard are unchanged. `admin_panel` no longer imports `fritz_utils` at all, and no code path on the chat surface consults `is_admin` — a privilege decision cannot be made from a name the user chose for themselves.
- **Phase 15 — the web chat has its own conversation thread.** `ask_stuff` derived the LangGraph `thread_id` from the username, so a `/chat` session and a Discord user with the same name shared one checkpoint. Since the chat cookie's username is self-asserted, anyone who signed in as `nick` could read and overwrite the real Discord conversation. `ask_stuff` now takes a keyword-only `thread_id`; the chat surface passes `web-<user>`. **Breaking:** existing web conversations appear to reset once, because they were living in the Discord thread. Set `CHAT_SHARE_DISCORD_THREAD=true` to keep the old shared behaviour — reasonable on a single-user instance where continuing one conversation across surfaces is the point. *(Superseded later in this release: the flag is retired and `IDENTITY_LINKS` replaces it — see "stable namespaced identity" above.)*
  - `user_id` still selects the memory namespace, so memories and schedules are unchanged and still shared across surfaces; only the immediate conversation splits.
  - The thread-id sanitiser for an explicit thread keeps `_` and `-`, so `web-alice` cannot collide with a Discord user literally named `webalice` (whose thread is stripped to alphanumerics). The separator is a dash, not a colon — a colon is illegal in Windows filenames.
  - `privacy.forget_conversation` gained an optional `thread_id`, so "New conversation" in the browser clears the web thread rather than silently destroying the Discord one.
  - `_load_chat_history` had its own inline copy of the thread-id regex; both paths now go through one `_chat_thread_id` helper, since a read path and a write path deriving the same id separately is precisely how the `/forget` bug for punctuated usernames happened.
- **Phase 15 — image uploads are sniffed, not trusted.** `chat_upload_image` checked only the `Content-Type` header the client declared, and `_safe_filename` kept whatever extension the client sent — `html` and `svg` both survive its character filter. So an HTML document uploaded as `image/png` with the name `evil.html` was written to `./temp_images` and served straight back by `/chat/assets` as `text/html` on the same origin as the chat session: stored XSS. Uploads are now decoded with Pillow (`verify()`, which parses structure without materialising pixels) and the stored extension is derived from the *sniffed* format, never from the filename or the declared type. The size cap deliberately stays ahead of the decode, so it both preserves the existing 413 behaviour and bounds what Pillow is asked to parse.
  - Verified against Pillow 12: `Image.open` rejects an HTML document, an SVG document, and even PNG magic bytes followed by HTML — the last of which a magic-byte prefix check would have let through.
  - The test fixture was itself the tell: `_TINY_PNG` was PNG magic followed by nulls, which Pillow does not accept. It only ever passed because nothing looked at the body. It is now a real 1×1 PNG.
- **Phase 15 — hardened asset serving.** `/chat/assets` returned a bare `FileResponse`, letting Starlette guess the media type from the extension. It now derives `Content-Type` from an explicit extension allowlist (anything else is a 404, so a stray executable extension cannot be served as a document), and adds `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox; frame-ancestors 'none'`, `Referrer-Policy: no-referrer` and a private cache header. Deliberately *not* `Content-Disposition: attachment` — thumbnails and generated images have to render inline, and the allowlist plus nosniff plus sandbox gets the same safety without breaking them.
  - Files under `./temp_images` are named `<user>_<ts>_<name>` by the upload route, so they are now only served to the user who uploaded them; a mismatch is a 404 plus a `chat_asset_denied` audit entry. Images under `./output` are generated as `generated_image-<ts>.png` with no owner recorded anywhere, so they remain readable by any signed-in chat user — closing that needs a registry and is not done here.
- **Phase 15 — the web chat requires a password.** `POST /chat/login` took a username and nothing else, so anyone who could reach `:8001` could type any name and get that person's conversation, memories and schedules. It now requires a shared `CHAT_PASSWORD`, compared with `secrets.compare_digest`; failures return 401, set no cookie, and are audited with the attempted username and client host.
  - **`CHAT_PASSWORD` does not fall back to `ADMIN_PANEL_PASSWORD`.** Giving someone chat access must never hand them the admin panel. **This means the chat surface is disabled after upgrading until you set `CHAT_PASSWORD` in `.env`** — that failure is deliberate and loud: login returns 503 naming the variable, and startup logs a warning explaining it.
  - New `CHAT_ALLOWED_USERS` narrows which names may be claimed (empty = any). The password is the perimeter and the username is only namespacing, so with a shared password and no allowlist one holder can still read another's thread. Per-user invite tokens are the real fix and are deferred, not rejected.
  - New `CHAT_COOKIE_SECURE` (default off, because the panel is normally reached over plain http through an SSH tunnel, where `Secure` would silently break login).
  - `chat_auth.py`'s docstring and the login page no longer claim there is no password. Honest scope: the route is unthrottled — `compare_digest` closes the timing channel but nothing rate-limits guessing. That is acceptable bound to 127.0.0.1 and not otherwise.
- **Phase 15 — web chat renders sanitised HTML.** `_render_markdown` now passes its output through `nh3` (`_sanitise_html`) before it reaches the browser. python-markdown deliberately passes raw HTML through verbatim, and `chat.html` renders replies with `| safe` into `innerHTML` — so a `<script>` tag Fritz could be talked into emitting, or one stored in a checkpoint and replayed by the history hydration, executed in the user's session. Both paths (the streamed `done` frame and the server-rendered history) go through the one helper.
  - The attribute allowlist is built from `dict(nh3.ALLOWED_ATTRIBUTES)` with `class` unioned onto `div`/`pre`/`code`/`span`/`table`. This matters twice over: `attributes=` *replaces* nh3's default map rather than extending it, so a hand-written map would silently drop `href` from `<a>` and `src`/`alt` from `<img>`; and nh3's defaults carry no entry for `div`/`pre`/`code`/`span` at all, so a plain `nh3.clean()` strips every Pygments class and reduces syntax highlighting to inert markup — no error, no failing test, since `<pre>` and the code text both survive. `test_codehilite_classes_survive_sanitiser` is the guard, and it must stay green before the highlighting work lands.
- **Phase 15 — `execute_command` containment.**
  - Child processes now get an explicit environment (`EXEC_ENV_PASSTHROUGH`, platform-aware default) instead of inheriting `os.environ`. Previously any user with a workspace could run `python -c "import os; print(os.environ['DISCORD_BOT_TOKEN'])"` and read the bot token, `ADMIN_PANEL_PASSWORD` and `CHAT_COOKIE_SECRET` straight out of the chat reply — verified live, not theoretical. `PATH` is always present (falling back to `os.defpath`); `MISTERFRITZ_SANDBOX=1` is injected so workspace scripts can detect the sandbox.
  - `argv[0]` must now be a bare program name. The allowlist check strips `.exe/.cmd/.bat/.ps1` before matching, so an absolute path to a workspace-authored `git.bat` used to pass validation and execute through `cmd.exe` on Windows. Paths in `argv[0]` are rejected outright.
  - New `EXEC_REQUIRE_ADMIN` (default `true`) restricts *only* `execute_command` to `fritz_utils.is_admin` users. Phase 7b correctly opened `read`/`write`/`edit`/`search`/`list` to every workspace holder, but it also opened program execution — and everything on the default allowlist that can evaluate caller-supplied code (`python -c`, `node -e`, `make`, `git -c`, `find -exec`, or simply `write_file` + `python script.py`) is arbitrary code execution. Denials are audited as `result="denied"`.
  - `MAX_EXEC_TIMEOUT` moved to `fritz_utils.EXEC_TIMEOUT_MAX` (env-configurable, default 30) and requested timeouts are clamped to `[1, max]` rather than only capped above — `subprocess.run(timeout=0)` expired immediately before.
  - `cd` left the default allowlist: with no shell and the cwd fixed to the workspace it was always a no-op.
  - The stale "this is ROOT_USER-gated" comment above the allowlist in `fritz_utils.py` has been corrected — it had been wrong since Phase 7b.
  - Honest scope: this contains env-var exfiltration and the allowlist bypass. It is not OS-level sandboxing. Under the default configuration an admin running a command can still read `~/.ssh`, `../.env` and `fritz.db`, and can make outbound network calls. Real containment needs a low-privilege user or a container per exec.

### Performance
- **Phase 15 — Discord event loop.** `/voice`, `/gen` and `/lore` ran multi-second-to-multi-minute CPU/GPU work *directly on the event loop*, so a single `/gen` froze heartbeats, streaming edits, `on_message` and every other user's interaction for the duration. All four blocking call sites now run on a shared bounded pool via the new `bot_adapters.run_blocking`, and `main_discord`'s three existing offloads moved onto the same pool so worker capacity is one number in one place instead of an unbounded default executor silently shared with discord.py's internals.
  - **`TTSEngine.generate_speech` was `async def` with no `await` anywhere in its body** — a lie that made `await`ing it run Coqui XTTS inference inline on the loop, and left the `tts.py` CLI printing `<coroutine object ...>` while synthesising nothing. It is now a real synchronous function, which fixes the CLI as a side effect, and takes an instance lock because Coqui's TTS object is not safe for concurrent inference.
  - **`image_generator.get_pipeline()` could double-load 7 GB of SDXL weights.** The lazy `if _pipeline is None` was unguarded and that race was reachable *before* this change — `generate_image` is also an agent tool, and the agent already runs in a worker thread. Both the load and the inference are now under a module-level lock, so the agent-tool path is covered too, not just `/gen`.
  - Per-cog `asyncio.Semaphore`s (`IMAGE_GEN_MAX_CONCURRENCY`, `TTS_MAX_CONCURRENCY`, both default 1) serialise the GPU commands. They live on the cog instance, not at module scope: asyncio primitives bind to the first loop that awaits them, so a module-level semaphore would wedge `/gen` permanently after a gateway reconnect built a new loop. Waiters park on the event loop rather than occupying a pool thread, and a queued `/gen` now says so.
  - `voice_slash` gained the failure path it never had — a raised exception previously left the deferred interaction spinning until Discord timed it out.
  - The three commands now use `METRICS.time_block`, which keeps the existing `/health` counters and adds an average-latency line for each.
- **Phase 15 — plan mode deleted; summarisation moved off the critical path.** Every single message — including "hi" — paid a mandatory FAST-model round trip to a planner node before the executor started, purely to decide whether the request needed decomposing. That is a decision the ReAct loop already makes for itself. `planner()` and `synthesizer()` are gone and the graph collapses to `START → executor → (summarize | END)`. Measured: a trivial message now reaches the executor with **zero** preceding LLM calls.
  - **Behavioural change worth watching:** multi-step requests no longer get an explicit decomposition plus a persona-voiced synthesis pass. The executor's system prompt carries the persona, so replies stay in character — but a genuinely multi-step request ("search for X, then summarise it against what you know about me") is the thing to compare before and after.
  - `EnhancedState` loses `plan`, `current_step`, `step_results` and `original_request`; `route_executor` and `should_continue` collapse into one edge, resolving a duplicated-threshold-check defect on the way.
  - **Summarisation no longer blocks the reply.** Crossing `SUMMARIZE_THRESHOLD` used to cost three LLM calls inline, two of them on the 20B model. The trim stays synchronous (it is what the node returns); the summary and profile extraction run on a daemon thread, because the summary is never fed back into `state["messages"]` — it only reaches Chroma. The coupling was in the code, not the data flow. Guarded per user so rapid turns cannot stack concurrent 20B summaries of nearly the same transcript. `SUMMARIZE_ASYNC=false` restores the old ordering.
  - **`SUMMARIZE_THRESHOLD` raised 15 → 30.** 15 was aggressive because each pass blocked a reply; in the background the trade flips toward longer in-thread memory.
  - **One 20B call deleted outright.** A full round trip to the thinking model existed only to invent a label string like `memory_of_pie`. `_make_memory_key` derives it locally — the key becomes Chroma metadata and contributes to the embedding alongside the summary, so a local slug is equivalent, and the module already built keys this way elsewhere (`fact_…`, `auto_…`).
  - **Native structured outputs** replace two "respond ONLY with JSON" prompts plus regex rescues. The memory-extraction one fixes a latent bug for free: its `re.search(r'\[.*?\]')` was non-greedy, so a reply containing a nested array silently truncated at the first `]` and dropped the remaining facts.
  - Dead per-request work removed: `ask_stuff` rebuilt the entire tool registry and system prompt on every call purely to feed a `logger.debug` (whose argument is evaluated even at INFO level), and `pretty_print()` wrote to stdout on every superstep regardless of log level.
- **Phase 15 — real token streaming.** The ReAct executor streamed whole per-superstep *state snapshots*, so nothing appeared until an entire `AIMessage` had been generated — the "streaming" was one update per completed reply. It now runs `agent.stream(..., stream_mode=["values", "messages"])`: `values` still drives final-state extraction and the tool-progress notices, while `messages` yields `AIMessageChunk` tokens as the model produces them.
  - **New callback contract:** `streaming_callback(delta, accumulated, restart)`. Consumers that replace content wholesale (Discord message edits) read `accumulated`; consumers that append (the web client) read `delta` and clear on `restart`. The arity changed in one commit across every consumer — a half-migration would raise `TypeError` on the first message to the other surface.
  - **`restart` is not decoration.** A model that narrates before calling a tool emits that preamble under one chunk id and the real answer under another. Verified against the installed langgraph with a scripted model: without a reset signal an appending client renders "Let me look. I found it sir." as a single reply.
  - **Web chat: O(n) instead of O(n²).** `token` frames now carry only the delta, with a new `reset` frame clearing the bubble on a segment boundary. Measured end-to-end: 177 wire bytes for a 165-character reply (**1.07×**), where the old cumulative format would have cost roughly 83×.
  - **Discord** still edits with the full accumulated body — the API requires it — but the worker→loop hop is now rate-limited by `DISCORD_STREAM_MIN_INTERVAL`, because at ~40 tokens/s the callback would otherwise queue 40 coroutines per second onto the gateway loop. `final_update()` always writes the complete text, so dropped hops lose nothing.
  - Plan mode still suppresses streaming for intermediate steps by design; the synthesizer streams the single answer the user sees, and its `invoke()` fallback now corrects the UI instead of leaving partial text stranded.
  - A hermetic canary test (`TestLangGraphMessagesContract`) pins the upstream behaviour this depends on — tuple shape, `AIMessageChunk` filtering, per-turn id stability — so a `langgraph`/`langchain-core` bump fails CI loudly instead of silently reverting to no streaming.
- **Phase 10 — quick wins.**
  - `config.json` parse is now cached via `functools.lru_cache`. Repeated key lookups during import no longer re-open the file.
  - Automatic memory extraction now skips trivial turns (user message < `MEMORY_EXTRACT_MIN_USER_CHARS` or reply < `MEMORY_EXTRACT_MIN_REPLY_CHARS`). Saves an LLM call + embedding writes on "hi" / "lol" turns. Skipped turns increment the `memory_extract_skipped` counter so the rate is visible in `/health`.
- **Phase 11 — per-tool latency observability.**
  - New `Metrics.time_block(name)` context manager: increments a counter, records latency, and tracks errors as a single atomic operation around a block.
  - New `time_tool(name)` helper that auto-prefixes with `tool.` for the canonical tool-call metric namespace.
  - All `agent_tools` tools and `file_tools` tools now record latency, not just call count. The admin overview page surfaces the per-tool average automatically, so it's now possible to see which tool is dragging response times.
- **Phase 12 — Ollama latency.**
  - New `prewarm.py` fires a 1-token request to every configured Ollama model (thinking, fast, vision, embedding) in a background daemon thread on `on_ready`. Eliminates the cold-load wait on the first user DM after a restart.
